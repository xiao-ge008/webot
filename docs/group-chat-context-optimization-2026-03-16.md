# 群聊上下文优化管理说明

更新时间：2026-03-16

## 目标

本次优化解决两个核心问题：

1. 群聊顶部运行态面板长期占据中栏高度，影响消息浏览与输入区可见面积。
2. 群聊上下文虽然已有压缩机制，但仍存在固定规则重复注入、近期消息重复回灌、成员之间互带无关上下文的问题。

优化后的目标是：

- 运行态信息移到右侧发言人区域，通过小图标弹出查看。
- 群聊上下文改为“群公共摘要 + 成员私有相关上下文 + 本轮调度信息”三层主结构。
- 保证每个成员只携带和自己相关的上下文，不再反复注入其他成员的完整近期发言。

## 当前实现落点

本次改动主要落在以下文件：

- `apps/frontend/src/pages/GroupChatPage.tsx`
- `apps/frontend/src/pages/ChatPage.tsx`
- `apps/frontend/src/types/group.ts`
- `apps/frontend/src/services/chat-session-store.ts`
- `apps/frontend/src/components/ui/popover.tsx`

## UI 优化规则

### 1. 运行态面板位置

原先位于群聊中栏顶部的运行态卡片已经移除。

新位置：

- 右侧边栏顶部
- “当前发言人”旁边的小图标按钮
- 点击后通过 `Popover` 弹出小面板

### 2. 面板展示内容

弹窗仅展示当前轮次必要信息：

- 队列状态
- 当前发言人
- 待处理数量
- 异步任务数量
- 最近一次压缩时间
- 群公共摘要
- 当前发言人的私有上下文摘要
- 仍在排队或执行中的队列项

设计原则：

- 运行态信息默认隐藏
- 不再长期占据群聊中栏高度
- 同时保留快速查看能力

## 上下文分层策略

### 1. 固定规则层

来源：`group.systemPrompt`

职责：

- 保存群规则
- 保存发言秩序
- 保存 `@` 转发规则
- 保存终止规则

要求：

- 固定规则只保留一份
- 运行时不再额外拼接大段重复说明
- 成员名单、白名单等稳定内容由群配置负责，不在每轮 prompt 中重复展开

### 2. 群公共摘要层

来源：`groupRuntime.memoryDigest`

职责：

- 表达当前用户目标
- 表达已确认结论
- 表达公开待处理事项
- 表达公开队列状态

数据结构：

- `summary`
- `goal`
- `decisions`
- `openQuestions`
- `speakerLine`
- `pendingLine`
- `lastUserIntent`
- `updatedAt`

使用原则：

- 优先用结构化摘要，而不是直接回放最近消息
- 一旦摘要存在，就不再常规注入原始近消息

### 3. 成员私有上下文层

来源：`groupRuntime.agentContextDigests`

职责：

- 只保存与某个成员相关的上下文
- 只保存该成员最近处理过的结论
- 只保存最近明确点名给该成员的事项
- 只保存当前仍与该成员有关的待办

数据结构：

- `agentId`
- `summary`
- `ownRecentLine`
- `mentionLine`
- `todoLine`
- `updatedAt`

使用原则：

- 发送给哪个成员，就只拼哪个成员的私有摘要
- 不把其他成员的完整历史带给当前成员

### 4. 本轮调度层

来源：运行时即时拼装

职责：

- 说明当前响应成员是谁
- 说明当前响应模式是主回复、接棒回复还是补位回复
- 说明当前是否被显式 `@`
- 说明当前群模式

使用原则：

- 只描述本轮任务
- 保持短小
- 不重复群规则正文

## Prompt 拼装规则

### 1. 主回复

主回复成员接收：

1. 群固定规则
2. 本轮调度信息
3. 群公共摘要
4. 当前成员私有摘要
5. 只和当前成员有关的队列信息
6. 必要时才回退到共享近消息摘要

### 2. 接棒回复

被 `@` 或被接棒的成员接收：

1. 群固定规则
2. 当前接棒说明
3. 群公共摘要
4. 该成员私有摘要
5. 该成员当前待办

额外要求：

- 不复读整段群历史
- 只处理交给自己的问题

### 3. 补位回复

自由发言模式下的补位成员接收：

1. 群固定规则
2. 补位说明
3. 群公共摘要
4. 该成员私有摘要

## 去重与去噪原则

必须遵守以下规则：

1. 同一事实只保留一份。
2. 已进入群公共摘要的内容，不再进入共享近消息。
3. 已进入成员私有摘要的内容，不再进入本轮调度说明。
4. `sharedContext` 只作为兜底策略使用，不能作为常驻上下文源。
5. 队列中已完成项只保留结论，不保留过程。
6. 其他成员的完整原始发言不能直接注入到当前成员 prompt。

## 摘要刷新规则

### 群公共摘要刷新

触发条件：

- 会话新增用户消息
- 会话新增成员消息
- 队列状态变化

更新内容：

- 最新用户目标
- 最近已确认结论
- 当前公开待处理事项
- 队列概况

### 成员私有摘要刷新

触发条件：

- 成员自己发言
- 有人明确 `@` 该成员
- 该成员进入队列或队列状态变化

更新内容：

- 该成员最近处理过的内容
- 最近点名给该成员的事项
- 当前只和该成员相关的待办

## 回退策略

当摘要还未生成或摘要为空时，允许回退到共享近消息：

- 使用 `buildGroupSharedContext`
- 仅保留少量最近消息
- 只作为临时兜底

禁止把回退路径重新变成常规路径。

## 后续维护约束

后续若继续扩展群聊上下文，必须遵守以下约束：

1. 新增字段优先落到结构化摘要，不要直接拼接自然语言长段。
2. 若某条规则已经进入 `group.systemPrompt`，运行时不得再次重复注入同义说明。
3. 若新增“成员状态”类数据，先判断它是否属于群公共信息还是成员私有信息。
4. 任何群聊 prompt 变更，都要检查是否让成员重新背上其他成员的无关上下文。
5. UI 上新增运行态信息时，优先放在右侧弹层，不要重新回到中栏常驻卡片。

## 验收要点

完成后应满足：

1. 群聊中栏顶部不再出现大块运行态卡片。
2. 右侧发言人区域存在小图标，点击可查看运行态面板。
3. 不同成员收到的系统前置上下文不再完全相同。
4. 群聊摘要存在时，不再把最近多条原始群消息重复注入 prompt。
5. 成员 prompt 中能看到群公共摘要和自己相关上下文，但看不到其他成员的大段无关历史。
